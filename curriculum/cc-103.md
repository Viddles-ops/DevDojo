## What a skill is ⓘ

A **skill** is a packaged set of instructions Claude Code loads on demand —
a recipe for one kind of task (build a .docx, review a diff, write a
runbook). Two triggers: you type `/<name>` (a *slash command*), or Claude
matches the task against the skill's description and invokes it itself.
Either way, the instructions load into the session and steer how that task
is done. Skills are prompts-as-code: versionable, shareable, improvable.

## Skill vs agent — the boundary that matters ⓘ

A **skill** changes how the *current* session does one task. An **agent**
is a separate worker with its own doctrine and tool allowlist. Rule of
thumb: recurring *procedure* → skill; recurring *responsibility with
guardrails* → agent. DeployGuard is an agent because restores need
standing rules, not just steps.

## When to build your own

The signal: you keep re-explaining the same procedure in prompts. Two real
candidates from this workspace: (1) the **lesson-authoring workflow** used
to build this curriculum (mine code/docs only → ~1 screen → Try it → Quiz
→ flip index.yaml → pytest); (2) the **handoff-writing format** from the
operator system. Both are procedures, not responsibilities — skills, not
agents. `/skill-creator` scaffolds one from a description.
