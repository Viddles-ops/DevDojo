# Extending Claude Code: skills, slash commands, and the steward you shipped

Claude Code has three extension points, and you now own real examples of
each. The choice between them follows one question: **when should Claude
know this?**

| Extension | Loads | Use for | Yours |
|---|---|---|---|
| `CLAUDE.md` | always, on session start | facts every session needs | every project |
| Agent (`.claude/agents/*.md`) | when work matches its `description` | a *role* with judgment, guardrails, tool limits | chief-operator, deploy-guard, **pipeline-steward** |
| Skill / slash command (`.claude/commands/*.md`) | when you type `/name` (or its trigger matches) | a *procedure* — steps you'd otherwise retype | this is your gap |

## Project-level vs user-level (the pipeline-steward difference)

Your first two agents live in `C:\Users\natee\.claude\agents\` — they follow
*you*. `pipeline-steward` lives in `oska_platform\.claude\agents\` — it
follows *the repo*: version-controlled, reviewed in a diff like code, and
loaded by any session opened in that folder, including a future analyst's.
Rule of thumb: doctrine about one project belongs in that project.

## The design lesson: give agents instruments, not memories

The steward's first draft memorized the chain order from three PowerShell
scripts. The shipped version doesn't memorize — it *reads*:
`config/pipeline_manifest.yaml` owns the order, `run_chain.py` executes it,
`verify_gold.py` judges the output, and `tests/` fail if anyone breaks an
ordering invariant. The agent routes, diagnoses, narrates. Recognize the
shape? It's ADR-012 (compute-then-narrate) applied to *operations*: the LLM
decides *which* deterministic thing runs and explains the result — it is
never the source of truth. When an agent's doctrine grows a table of facts,
that's the smell: turn the table into a file the agent reads, or a script
it runs.

## Slash commands: the cheapest extension you're not using

A slash command is just a markdown prompt file —
`.claude/commands/verify-build.md` containing "Run `py verify_gold.py`,
then report the status block and flag anything failing" becomes
`/verify-build` in any oska_platform session. No frontmatter required, no
tools list. Anything you've typed to Claude twice is a candidate:
post-curation rotation, quarantine triage, the monthly-refresh checklist.

## Try it

In `oska_platform\`, create `.claude\commands\verify-build.md` with the one
sentence above, start a session, and type `/verify-build`. Then open
`.claude\agents\pipeline-steward.md` and find the two places its doctrine
*points at* a source of truth instead of restating it (§3 and §4) — that's
the instruments-not-memories rule in the wild.
